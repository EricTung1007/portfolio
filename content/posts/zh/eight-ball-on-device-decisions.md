魔法八號球是一種幾乎不需要教學的互動介面。心裡想一個問題，搖動黑色球體，透過小小的視窗讀取答案。答案可能肯定、否定，也可能模稜兩可。它最重要的特性是隨機：這顆球並不知道提問者是誰，也不理解問題的背景。

獨立開發並已上架的 iOS App [《八號球》](https://apps.apple.com/tw/app/%E5%85%AB%E8%99%9F%E7%90%83/id6827388818?l=en-GB)，從這個熟悉的儀式出發，加入另一個產品問題：**如果同一顆球還可以幫人比較選項、留下決策紀錄，它會成為什麼樣的工具？**

這個小型產品有一個很值得討論的矛盾。占卜玩具有趣，正因為它不需要講道理；決策輔助工具有用，則取決於使用者能否理解建議的依據。當兩種目的共用一套介面，最重要的設計工作就是讓使用者知道，自己此刻得到的究竟是哪一種答案。

## 兩種模式，兩種不同的承諾

《八號球》保留傳統 Magic 8 Ball 的 **Classic 模式**，使用熟悉的二十種答覆；另一個 **Truth 模式**則以 Core ML 裝置端模型支援多選項比較。它們可以共享同一個視覺符號，但對使用者的責任不同。

Classic 幾乎不要求輸入成本。想好問題，搖動裝置或操作球體，就能看到一個回覆。它提供的是即時回饋、懸念，以及把無傷大雅的小決定交給機率的樂趣。隨機結果不需要被包裝成有依據的判斷。

Truth 改變了任務形式。使用者可以把 **2 至 8 個候選選項**放在一起比較。當產品開始比較具名的選項，它的結果就不再只是戲劇化的預言。使用者自然會想知道：系統考慮了哪些因素？這些因素是否符合自己的偏好？結論可以被修正嗎？

| Classic | Truth |
| --- | --- |
| 一個問題、一個趣味答覆 | 比較多個明確列出的候選選項 |
| 隨機性是體驗的一部分 | 比較結果需要讓人理解其限制 |
| 速度、回饋與氛圍最重要 | 清楚表達與使用者自主權更重要 |
| 答案可以看過就忘 | 選擇可能值得日後重新檢視 |

產品不應因為同時具有 AI 功能，就讓隨機答案看起來像客觀分析；也不應把模型提供的偏好排序包裝成唯一正解。決策工具可以協助整理想法，但最終仍由使用者判斷。

## 為什麼要留下決策日誌？

單次抽出的答案很容易被忘記。決策日誌則把一次選擇保留下來。《八號球》提供記錄決策、筆記及事後回顧的空間。

這讓 App 的用途不再停留於「現在選哪個」。例如，今天比較了幾個選項，最後選擇其中之一；一段時間後，可以再回頭看看當時為什麼做出決定，以及事情後來如何發展。

日誌真正有價值的地方，不是證明 App 猜得準不準，而是建立**原本的選項、當時的理由，以及後來的結果**之間的關聯。有些選擇結果不好，只是遇到不可預見的變化；有些選擇結果很好，過程卻可能只是碰巧。缺乏紀錄時，很難把這兩者分開。

這也形成新的介面要求。歷史記錄必須保留足夠脈絡，才能在幾週或幾個月後讀得懂。只有一句「推薦 A」，卻沒有原本的選項及註記，其實無法提供多少反思價值。

## Core ML 的真正價值與界線

Core ML 是 Apple 提供的裝置端機器學習框架，讓 App 能在 Apple 平台執行模型。《八號球》的 Truth 模式以此提供本機選項比較，而不必每次選擇都仰賴雲端對話。

這是一個有意義的系統邊界。對於能完整在裝置端執行的推論，本機模型可以減少遠端 API 依賴，省去網路往返等待，並讓輸入不必為了該次推論傳送給外部伺服器。對開發者而言，本機推論也不會產生每次請求的雲端推論費用。

但使用 Core ML 不代表模型自然就「理解」個人偏好，更不能只看模型存在與否來判斷建議品質。光靠商店介紹，也無法確認模型架構、訓練資料、量化方式、輸入特徵、實際正確率或裝置上的效能。裝置端推論同樣不代表購買驗證等其他流程必然可以離線完成。

對決策工具而言，更值得檢查的是結果是否反映使用者輸入的選項、能否調整評估準則，以及介面有沒有清楚表達不確定性。這些比模型究竟有幾十億參數，更直接影響產品是否好用。

## 讓趣味互動與認真比較共存

《八號球》的產品設計將容易進入的經典互動，與更適合深度比較的進階功能放在同一個 App。進階能力包括加權決策、錦標賽式選項比較，以及更完整的決策紀錄。

這些功能不是同一種流程的不同外觀。加權決策讓不同條件有不同重要性，適合在意評估準則的人；錦標賽則把一大組選項拆成連續的兩兩比較，讓使用者每次只需處理較小的範圍。兩種方法都會改變思考成本，但不會自動保證選擇正確。

因此，視覺設計不能只追求球體是否精緻、動畫是否流暢，還必須讓人辨識：目前得到的是機率抽選、系統比較，還是自己設定規則後的結果。這些狀態的切換，才是整套決策介面最重要的地方。

付費模式也值得從產品層面理解。免費的經典玩法本身就能完成一次互動；進階付費則對應更深入的比較與紀錄需求。這是一種合理的功能分層方式，但是否具有良好的轉換率，仍需要真正的使用及付費資料，而不能只靠功能表推定。

## 上架是一個完整的工程交付

一款 App 在開發者手機上能夠執行，與正式上架是兩件事。App Store 發布意味著產品需要面對安裝、裝置差異、商店文案、輔助使用、隱私揭露、審核規則與購買流程。《八號球》已經有正式的 [台灣 App Store 頁面](https://apps.apple.com/tw/app/%E5%85%AB%E8%99%9F%E7%90%83/id6827388818?l=en-GB)，因此可以作為一個實際交付的獨立 iOS 作品來討論，而不只是尚未落地的 UI 概念。

它的規模不大，反而讓各個設計問題更清楚：一個刻意簡單的經典互動、一個涉及機器學習的比較模式、一套能保留選擇脈絡的日誌，以及一條區分免費與付費能力的產品界線。單獨描述每個功能都不難；真正的工作是讓它們在同一個產品裡維持一致的期待。

這個專案的啟示並不是「每個決定都需要 AI」。絕大部分決定其實不需要。更值得保留的設計原則是：**一個介面應清楚告訴人們，眼前的答案從何而來。** 有時隨機性本身就是樂趣；有時比較能協助整理複雜選項。好的產品必須尊重這兩者的區別。
