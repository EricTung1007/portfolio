Minerva’s Den 的硬體邊界是一台配備 32GB 統一記憶體的 Mac mini M4。重點不只是模型跑不跑得動，而是模型、KV Cache、工具與 Agent 同時運作時，還有多少真正可用的資源。

## 一筆實測紀錄

2026 年 11 月 5 日，在 Python 程式碼情境、4,096 個輸入 Token 與 128 個輸出 Token 的單次測試中，記錄到：

| 指標 | 結果 |
| --- | --- |
| Prompt 處理速度 | 64.0 tokens/s |
| 生成速度 | 11.1 tokens/s |
| 首 Token 延遲 | 64,035.1 ms |
| 每 Token 時間 | 91.0 ms |
| 端到端耗時 | 75.6 s |
| 記憶體峰值 | 19.4 GB |

這是**歷史單次量測**，不是跨模型或跨後端的正式比較。原始紀錄尚缺完整模型版本、量化與推論設定，不能以此推斷某個模型必然較慢。

## 工程意義

約 64 秒的首 Token 延遲對多步驟 Agent 相當昂貴，因為每次重新提交長上下文都可能累積等待時間。19.4GB 的峰值也代表多代理、長上下文與背景服務需要更謹慎配置。

32GB 減去 19.4GB 不能直接當作可用額度，因為 macOS、其他程式、KV Cache 與推論緩衝區都會競爭統一記憶體。

## 下一輪測試

1. 固定模型版本、量化格式與推論後端。
2. 使用相同工作負載測試不同上下文長度。
3. 比較單請求與並行請求。
4. 分開量測模型載入、Prefill 與 Decode。
5. 加入每 GB 與每分鐘任務成功率等指標。

最終目標不是單純追求 tokens/s，而是讓整個 Agent 系統穩定運作。
