研究 Agent 可以把先前的對話、可重用程式碼與實驗經驗帶到下一個任務。這看起來像是持續累積專業知識，但真正需要驗證的是：它能改善**最終模型成果**，還是只讓下一次實驗更快開始？

2026 年 11 月 3 日，Qin 等人發布預印本 [*From AutoResearch to Continual AutoResearch: Do Agents Learn Across Tasks?*](https://arxiv.org/abs/2611.05108)，對這個問題進行相對嚴謹的控制比較。結論比「Agent 有永久記憶就會越來越強」更有限：**持續保留狀態能穩定改善前期研究效率，卻無法保證最終解答更好。**

## 測試的是跨任務經驗，不是重新訓練模型權重

原始的 [Karpathy autoresearch](https://github.com/karpathy/autoresearch) 讓 Agent 修改 `train.py`，在固定評估方式與五分鐘訓練預算下嘗試不同配置，依 validation bits per byte（`val_bpb`，驗證資料的每位元組資訊成本）決定是否保留修改。官方原版使用 NVIDIA GPU，已在 H100 上測試，並不是開箱即用的 Mac MPS 或 MLX 模型最佳化工具。

Continual AutoResearch 換了一個問題：如果 Agent 必須連續解決**一系列有關聯的研究任務**，先前經驗能否轉移？研究者讓相同 Agent 在相同任務順序、資料與預算下，分別使用「持續保留狀態」與「每個任務重新開始」兩種模式。測試涵蓋九種任務家族，包括合成 AutoML、符號迴歸、時間序列預測及表格資料 AutoML。單項任務預設有 **30 分鐘**預算，彙總結果中每個模型有 **32 個可觀察跨任務轉移的任務**。

研究分別衡量第一個有效解答的品質、固定時間內的搜尋進展，以及在隱藏測試集上的最終表現。研究沒有透過修改模型權重來儲存經驗；這裡的「學習」指的是重用執行狀態、程式、指令與策略。

研究透過五個模型各自原生的 CLI Harness 執行。這讓同一模型的持續模式和重置模式具有可比較性；不同模型之間的差異則仍可能受到 Harness 影響。

## 數字清楚區分了搜尋效率與最後的品質

論文 [Table 2](https://arxiv.org/abs/2611.05108) 用**標準化獎勵分數**呈現持續模式減去重置模式的差距。Time-convergence 指標同時獎勵「較早找到候選答案」與「候選答案品質較好」，**不是**每秒 Token 數，也不是效能提升百分比。

| 模型與原生 Harness | 搜尋過程效率差距 | 最終成果差距 |
| --- | ---: | ---: |
| Kimi K3 / OpenCode | +21.3 | +0.4 |
| Sonnet 4.6 / Claude Code | +20.9 | +7.6 |
| Opus 5 / Claude Code | +7.5 | -0.9 |
| GPT-5.6-Sol / Codex | +6.1 | -0.8 |
| GPT-5.4 / Codex | +3.0 | +0.2 |

五個受測 Agent 在搜尋過程指標都因保留狀態而改善，但只有 Sonnet 的**最終成果**呈現明顯平均增益。論文指出，持續模式能更早產生第一個有效解答；其中 Kimi K3 平均提早 **9.2 分鐘**，Sonnet 4.6 平均提早 **8.6 分鐘**。重置模式通常會在後半段追上。當任務只經過四分之一預算時，持續模式平均領先 +24.0 分；到截止時間只剩 +1.2 分。

更有意思的是一項嚴格控制：研究者扣除第一個有效解答原本帶來的優勢後，**五個 Agent 都不再有搜尋最佳化的正向優勢**。目前觀察到的主要收益來自起步較快、第一個候選品質較好，並不足以證明持續記憶讓後續搜尋能力普遍提高。

以上是**論文作者的實驗結果**，並非第三方獨立重現。大多數模型只做一組配對實驗，只有 GPT-5.6-Sol 進行三組重複比較；各任務家族通常也只有三至五個任務。

## 相關記憶可能有用，也可能誤導

研究者另做記憶消融實驗：每次都開啟新的 Agent Session，再提供先前實驗整理成的「insight cards」。每張卡包含主張、證據、信心程度、適用範圍及失效條件。研究比較三種情況：來自相同任務系列的卡片、來自無關系列的打亂卡片，以及完全不提供卡片。

這項實驗只包含 **Energy-systems 系列中四個可測試經驗轉移的任務**，不能直接外推到所有情境。和打亂卡片相比，相關卡片讓 Opus 5、GPT-5.4、GPT-5.6-Sol 的初始品質分別增加 +2.6、+5.9、+3.9 分；但這三個模型的搜尋過程效率反而下降，差距分別是 -15.5、-0.9、-27.3 分。Sonnet 則出現不同方向的結果。論文也記錄了 Agent 過度沿用先前的建模假設，以及因開發集回饋不可靠而換掉原本較佳候選方案的案例。

這代表儲存更多文字不一定等於得到更有效的記憶。研究系統必須有機制能在資料分布、目標或運算環境改變時，**撤回或修正**過去的經驗。

## 自主實驗 Harness 應該保留什麼？

可以用簡短、可稽核的實驗紀錄，取代無限制增長的聊天紀錄。例如：

    hypothesis: "每日週期特徵可能改善每小時需求預測"
    evidence: "實驗 ID；驗證切分；相較基準的變化"
    scope: "存在重複日週期的每小時能源序列"
    countercheck: "和不使用週期特徵的基準比較"
    status: "待驗證的經驗，而非通用規則"

這是根據研究結果提出的**工程設計方向**，不是論文已測得的獨立成果，也不表示 Ouroboros 已經實作。每項新實驗只應讀取與當前任務相關的紀錄，重新檢查其適用性，並保留不受調參影響的最終測試集。應在相同運算預算下比較乾淨 Session 與持續 Session，分開量測「多久產生第一個有效結果」、「過程中曾找到的最佳候選」與「最終選中的方案」。否則 Agent 可能只是記住一份可運作的程式，就被誤認為研究能力進步。

**結論：**當研究時間很短、環境初始化昂貴時，保留狀態有實際價值，因為證據支持更快得到可用結果。但它無法保證最終模型品質提高。對自我改進實驗系統而言，第一個值得持續累積的資產應是**可稽核的實驗、明確適用範圍且可修正的經驗，以及保留獨立測試的候選選擇機制**。下一個真正值得測試的問題，是具來源與適用範圍的選擇性記憶，能否在相同本地工作負載上勝過完全保留狀態與每次重置。
